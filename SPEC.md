## 1. Назначение

"Базальтовая Улитка" — одноместное наземное средство передвижения с каменными колёсами и сворачивающимся панцирем. В раскрытом состоянии оно медленно преодолевает дороги, каменистую почву и песок. После сворачивания панцирь становится наружной беговой поверхностью колёс, позволяя быстро катиться по дороге. Приложение моделирует расход энергии, пройденный путь и переключение режимов по командам пилота.

![Базальтовая Улитка](assets/basalt-snail.png)

## 2. Стихия и конструкционный элемент

**Стихия:** земля. **Обязательный конструкционный элемент проекта:** каменные колёса, обеспечивающие контакт с грунтом и наземное движение. Их диаметр задаётся публичной характеристикой `wheel_diameter_m` и влияет на скорость во всех разрешённых режимах.

В режиме `crawl` панцирь раскрыт, колёса вращаются по отдельности. В режиме `roll` панцирь свёрнут и соединяет колёса в общую округлую беговую поверхность.

Ограничения среды:

- `road` — дорога: разрешена в обоих режимах.
- `rock` — каменистая почва: разрешена только в `crawl`.
- `sand` — песок: разрешён только в `crawl`.
- `water` и `air` — известные, но недоступные стихии; транспорт не плавает и не летает.

## 3. Публичный интерфейс

### 3.1. Класс и модуль

Класс: `BasaltSnail`. Модуль: `basalt_snail.py` в корне проекта. Все классы исключений из раздела 6 экспортируются из этого же модуля. Внутреннее устройство класса не регламентируется. Параметры конструктора и методов допускают позиционную и именованную передачу по именам из сигнатур.

### 3.2. Конструктор и общие правила параметров

```python
def __init__(
    self,
    name: str,
    mass_kg: float,
    wheel_diameter_m: float = 1.0,
    energy: float = 100.0,
) -> None:
```

| Параметр | Тип входа | Единица | Допустимые значения | По умолчанию |
| --- | --- | --- | --- | --- |
| `name` | `str` | — | Непустая строка после `strip()` | Обязателен |
| `mass_kg` | `int` или `float`, кроме `bool` | кг | `[100.0, 500.0]` | Обязателен |
| `wheel_diameter_m` | `int` или `float`, кроме `bool` | м | `[0.5, 2.0]` | `1.0` |
| `energy` | `int` или `float`, кроме `bool` | ед. | `[0.0, 100.0]` | `100.0` |

Все числовые входы конструктора и методов должны быть конечными: `NaN`, `+inf` и `-inf` запрещены. Числовые характеристики и результаты сохраняются/возвращаются как `float`. Внешние пробельные символы имени удаляются через `strip()`; внутренние сохраняются. Одинаковые имена у разных объектов разрешены.

Проверки конструктора идут по параметрам: `name`, `mass_kg`, `wheel_diameter_m`, `energy`. Для каждого параметра сначала проверяется тип, затем значение. Сообщения приведены в разделе 6.

После создания `distance_km == 0.0`, `mode == "crawl"`. Объекты независимы: изменение одного не изменяет другой.

### 3.3. Публичные атрибуты и инварианты

| Атрибут | Тип | Единица | Доступ | Значение/назначение |
| --- | --- | --- | --- | --- |
| `name` | `str` | — | Только чтение | Нормализованное имя |
| `mass_kg` | `float` | кг | Только чтение | Масса; постоянна после создания |
| `wheel_diameter_m` | `float` | м | Только чтение | Диаметр колёс; постоянен после создания |
| `energy` | `float` | ед. | Только чтение | Текущий запас, `[0.0, 100.0]` |
| `distance_km` | `float` | км | Только чтение | Общий путь; начинается с нуля и не уменьшается |
| `mode` | `str` | — | Только чтение | Ровно `crawl` или `roll` |

Прямое присваивание любому из этих атрибутов и его удаление (`del vehicle.energy` и аналогично для остальных атрибутов) вызывают `AttributeError` и не изменяют состояние. Пилот меняет состояние только методами раздела 3.4.

**Атомарность:** любой вызов, завершившийся исключением, оставляет все публичные атрибуты прежними. Неизменность проверяется точным сравнением значений и типов всех шести атрибутов, без допуска для чисел. Проверки выполняются до расхода энергии и изменения пути/режима. Нет автоматической заправки, смены режима, движения или восстановления энергии.

### 3.4. Методы

#### 3.4.1. `calculate_energy`

```python
def calculate_energy(self, distance_km: float, terrain: str) -> float:
```

Рассчитывает требуемую энергию без изменения состояния. `distance_km` — конечное число `int`/`float`, кроме `bool`, строго больше нуля. `terrain` — строка из `road`, `rock`, `sand`, `water`, `air`; регистр важен, пробелы не удаляются.

| Среда | Базовый расход, ед./км |
| --- | --- |
| `road` | `5.0` |
| `rock` | `10.0` |
| `sand` | `15.0` |

Расход: `(distance_km * базовый_расход) * (mass_kg / 200.0)`. Скобки и группировка операций обязательны: сначала вычисляются произведение дистанции на базовый расход и отношение массы к `200.0`, затем их произведение. Вычисления выполняются в Python `float`, без промежуточного округления и перестановки операций. На дороге формула одинакова для `crawl` и `roll`. Диаметр колёс влияет только на скорость. Метод возвращает `float`, даже если имеющейся энергии недостаточно.

Например, для массы `150.5`, дистанции `0.3` и среды `sand` результат равен `3.3862499999999995`. Проверка порядка вычислений: `TC_M_09`.

Исключения: `TypeError`/`ValueError` при неверных параметрах; `UnsupportedTerrainError` для `water`/`air`; `RollingTerrainError` для `rock`/`sand` при `mode == "roll"`. `InsufficientEnergyError` этот метод не вызывает.

#### 3.4.2. `move`

```python
def move(self, distance_km: float, terrain: str) -> float:
```

Перемещает транспорт в указанной среде. Параметры, формула расхода и проверки среды такие же, как у `calculate_energy`. Возвращает время поездки в **часах**: `distance_km / скорость`.

| Режим | Среда | Скорость, км/ч |
| --- | --- | --- |
| `crawl` | `road` | `10.0 * wheel_diameter_m` |
| `crawl` | `rock` | `5.0 * wheel_diameter_m` |
| `crawl` | `sand` | `2.0 * wheel_diameter_m` |
| `roll` | `road` | `40.0 * wheel_diameter_m` |

Если `energy >= расход`, вызов успешен: `energy` уменьшается на вычисленный расход, общий путь (`self.distance_km`) увеличивается на значение параметра `distance_km`. Режим, имя, масса и диаметр колёс сохраняются. Сравнение запаса с расходом выполняется точно для полученных значений `float`, без допуска. Равенство энергии вычисленному расходу разрешено: остаток ровно `0.0`. Малый положительный остаток не округляется до нуля: при массе `150.5`, дистанции `0.3`, среде `sand` и запасе `3.38625` он равен `4.440892098500626e-16`. Если запас равен `3.3862499999999995`, остаток ровно `0.0`; при запасе `3.386249999999999` возникает отказ. Проверки: `TC_M_18`.

Если `energy < расход`, возникает `InsufficientEnergyError`. Остальные исключения совпадают с `calculate_energy`.

Для обоих методов порядок проверок:

1. Тип и значение `distance_km`.
2. Тип и принадлежность `terrain` к пяти известным средам.
3. Доступность стихии (`water`/`air`).
4. Совместимость среды с режимом (`rock`/`sand` в `roll`).
5. Только для `move`: достаточность энергии.

#### 3.4.3. `fold_shell`

```python
def fold_shell(self) -> None:
```

Сворачивает панцирь. Параметров нет. В `crawl` при `energy >= 10.0` уменьшает энергию на `10.0` и переводит `mode` в `roll`. Возвращает `None`. Путь не меняется.

Сначала проверяется режим: в `roll` возникает `ShellStateError` даже при нулевой энергии. Затем проверяется энергия: при `energy < 10.0` возникает `InsufficientEnergyError`. Другие атрибуты не меняются.

#### 3.4.4. `unfold_shell`

```python
def unfold_shell(self) -> None:
```

Раскрывает панцирь. Параметров нет. В `roll` при `energy >= 5.0` уменьшает энергию на `5.0` и переводит `mode` в `crawl`. Возвращает `None`. Путь не меняется.

Сначала проверяется режим: в `crawl` возникает `ShellStateError` даже при нулевой энергии. Затем проверяется энергия: при `energy < 5.0` возникает `InsufficientEnergyError`. Другие атрибуты не меняются.

#### 3.4.5. `refuel`

```python
def refuel(self, amount: float) -> None:
```

Заряжает аккумулятор. `amount` — конечное число `int`/`float`, кроме `bool`, строго больше нуля, в единицах энергии. Устанавливает `energy = min(100.0, energy + amount)`, возвращает `None`. Избыточный заряд отбрасывается; зарядка полного аккумулятора разрешена. Дробный заряд не округляется до целого: при энергии `60.0` вызов `refuel(0.25)` возвращает `None` и оставляет энергию `60.25` (`TC_M_24`). Остальные атрибуты сохраняются. Неверный тип вызывает `TypeError`, неверное значение — `ValueError`.

#### 3.4.6. `get_status`

```python
def get_status(self) -> dict[str, str | float]:
```

Возвращает новый словарь со **всеми и только** следующими ключами: `name`, `mass_kg`, `wheel_diameter_m`, `energy`, `distance_km`, `mode`. Значения совпадают с одноимёнными атрибутами и их типами. Вызов ничего не печатает, не изменяет транспорт и не вызывает доменных исключений. Изменение возвращённого словаря не меняет транспорт; ранее полученный словарь не меняется при новых командах.

## 4. Сценарии и тест-план

### 4.1. Модульные тесты (AAA)

Модульные тесты используют паттерн AAA (Arrange–Act–Assert). Независимые варианты одной проверки выполняются через `subTest` на свежих объектах. Для отрицательных тестов проверяется класс исключения, точное сообщение и неизменность полного состояния.

Примеры модульных проверок:

| TC | Arrange | Act | Assert |
| --- | --- | --- | --- |
| `TC_M_16` | Масса 200 кг, колёса 1 м, энергия 100, `crawl` | `move(2.0, "rock")` | Время `0.4`, энергия `80.0`, путь `2.0`, режим `crawl` |
| `TC_M_19` | Энергия `4.0`, начальный режим | `move(1.0, "road")` | `InsufficientEnergyError`, полное состояние прежнее |
| `TC_M_20` | Энергия `100.0`, начальный режим | `fold_shell()` | `None`, энергия `90.0`, режим `roll`, путь `0.0` |
| `TC_M_25` | Энергия `50.0`, начальный режим | `refuel(1000.0)` | `None`, энергия `100.0`, путь и режим прежние |

### 4.2. Сценарные тесты (Given–When–Then)

Пилот — **тестовая обёртка**, не отдельная модель приложения. `Pilot(vehicle)` принимает готовый транспорт и делегирует команды `travel(distance_km, terrain)`, `estimate(distance_km, terrain)`, `roll_up()`, `open_shell()`, `recharge(amount)`, `status()` одноимённым по смыслу методам транспорта. Он не хранит копию состояния и не перехватывает исключения. Сценарии выполняются через пилота; состояние проверяется по полному словарю `status()` после каждого значимого шага.

Если не указано иное: имя `Улитка-1`, масса `200.0`, диаметр `1.0`, энергия `100.0`, режим `crawl`, путь `0.0`. В записях ниже `(энергия, путь, режим)` задаёт меняющиеся поля статуса; имя, масса и диаметр остаются значениями Given.

#### 4.2.1. Доставка через три вида грунта — `TC_S_01`

**Given:** пилот управляет транспортом с параметрами по умолчанию.  
**When:** едет `2.0` км по `road`.  
**Then:** время `0.2` ч, статус `(90.0, 2.0, crawl)`.  
**When:** едет `1.0` км по `rock`.  
**Then:** время `0.2` ч, статус `(80.0, 3.0, crawl)`.  
**When:** едет `1.0` км по `sand`.  
**Then:** время `0.5` ч, статус `(65.0, 4.0, crawl)`.

#### 4.2.2. Скоростной участок и каменная тропа — `TC_S_02`

**Given:** стандартный транспорт.  
**When:** пилот сворачивает панцирь, едет `1.0` км по дороге, раскрывает панцирь и едет `2.0` км по камням.  
**Then:** статусы последовательно `(90.0, 0.0, roll)`, `(85.0, 1.0, roll)`, `(80.0, 1.0, crawl)`, `(60.0, 3.0, crawl)`; поездки занимают `0.025` и `0.4` ч.

#### 4.2.3. Спасение после полного разряда — `TC_S_03`

**Given:** начальная энергия `20.0`.  
**When:** пилот едет `2.0` км по камням.  
**Then:** время `0.4` ч, статус `(0.0, 2.0, crawl)`.  
**When:** пытается свернуть панцирь.  
**Then:** `InsufficientEnergyError`, состояние прежнее.  
**When:** заряжает на `15.0`, сворачивает панцирь и едет `1.0` км по дороге.  
**Then:** статусы `(15.0, 2.0, crawl)`, `(5.0, 2.0, roll)`, `(0.0, 3.0, roll)`; поездка `0.025` ч.  
**When:** пытается раскрыть панцирь.  
**Then:** `InsufficientEnergyError`, статус `(0.0, 3.0, roll)`.

#### 4.2.4. Зарядная станция и песчаный объезд — `TC_S_04`

**Given:** начальная энергия `25.0`.  
**When:** пилот сворачивается и едет `3.0` км по дороге.  
**Then:** статусы `(15.0, 0.0, roll)`, `(0.0, 3.0, roll)`; время `0.075` ч.  
**When:** заряжает на `200.0`, раскрывается и едет `2.0` км по песку.  
**Then:** статусы `(100.0, 3.0, roll)`, `(95.0, 3.0, crawl)`, `(65.0, 5.0, crawl)`; время `1.0` ч.

#### 4.2.5. Панцирь заблокирован без энергии — `TC_S_05`

**Given:** начальная энергия `10.0`.  
**When:** пилот сворачивается.  
**Then:** статус `(0.0, 0.0, roll)`.  
**When:** повторно сворачивается, пытается ехать по камням, затем раскрыться.  
**Then:** соответственно `ShellStateError`, `RollingTerrainError`, `InsufficientEnergyError`; после каждого отказа статус прежний.  
**When:** заряжает на `5.0` и раскрывается.  
**Then:** статусы `(5.0, 0.0, roll)`, `(0.0, 0.0, crawl)`.

#### 4.2.6. Тяжёлая улитка с большими колёсами — `TC_S_06`

**Given:** масса `400.0`, диаметр `2.0`, энергия `100.0`.  
**When:** пилот оценивает поездку `1.0` км по камням.  
**Then:** расход `20.0`, статус `(100.0, 0.0, crawl)`.  
**When:** едет `1.0` км по дороге, сворачивается, едет ещё `2.0` км по дороге, раскрывается и едет `1.0` км по камням.  
**Then:** статусы `(90.0, 1.0, crawl)`, `(80.0, 1.0, roll)`, `(60.0, 3.0, roll)`, `(55.0, 3.0, crawl)`, `(35.0, 4.0, crawl)`; времена `0.05`, `0.025`, `0.1` ч.

#### 4.2.7. Отказы на границе стихии и восстановление маршрута — `TC_S_07`

**Given:** начальная энергия `30.0`.  
**When:** пилот сворачивается и едет `1.0` км по дороге.  
**Then:** статусы `(20.0, 0.0, roll)`, `(15.0, 1.0, roll)`; время `0.025` ч.  
**When:** пытается ехать `1.0` км по воде, воздуху и камням.  
**Then:** `UnsupportedTerrainError`, `UnsupportedTerrainError`, `RollingTerrainError`; каждый отказ сохраняет статус.  
**When:** заряжает на `10.0`, раскрывается и едет `1.0` км по камням.  
**Then:** статусы `(25.0, 1.0, roll)`, `(20.0, 1.0, crawl)`, `(10.0, 2.0, crawl)`; время `0.2` ч.

#### 4.2.8. Повтор команды после недостаточного заряда — `TC_S_08`

**Given:** начальная энергия `12.0`.  
**When:** пилот сворачивается и оценивает поездку `1.0` км по дороге.  
**Then:** статус `(2.0, 0.0, roll)`, оценка `5.0` без изменения состояния.  
**When:** пытается выполнить эту поездку.  
**Then:** `InsufficientEnergyError`, статус прежний.  
**When:** заряжает на `3.0`, повторяет поездку и дважды запрашивает статус.  
**Then:** после зарядки `(5.0, 0.0, roll)`, после поездки и каждого запроса `(0.0, 1.0, roll)`, время `0.025` ч.

### 4.3. Test Case Specification и организация тестов

[TEST_CASES.md](TEST_CASES.md) содержит 40 уникальных ID: `TC_M_01`–`TC_M_32` (module, 80%) и `TC_S_01`–`TC_S_08` (scenario, 20%). Один ID соответствует одному тест-методу; варианты `subTest` явно перечислены в TCS. Имя метода и docstring содержат точный ID. Числа с плавающей точкой сравниваются с точностью 7 десятичных знаков через `assertAlmostEqual`, строковые значения, ключи, типы и сообщения — точно. Исключения: состояние до и после любого ожидаемого исключения сравнивается точно по всем шести значениям и их типам — как в модульных тестах, так и через пилота в сценарных. Результат дробного расчёта в `TC_M_09`, остатки энергии в `TC_M_18` и дробный заряд в `TC_M_24` также сравниваются точно через `assertEqual`. Допуск не должен скрывать изменение состояния, перестановку операций или округление малого остатка.

Модульные тесты находятся в `tests/test_basalt_snail.py`, сценарные — в `tests/test_scenarios.py`, пилот — в `tests/pilot.py`. Проверяются только публичные атрибуты, методы и исключения. Тесты не обращаются к приватным полям и не записывают состояние напрямую.

## 5. Граничные случаи

1. **Нижние/верхние границы параметров:** масса `100.0` и `500.0`, диаметр `0.5` и `2.0`, энергия `0.0` и `100.0` разрешены. Для `move` и `calculate_energy` параметр `distance_km` должен быть строго больше нуля; для `refuel` параметр `amount` должен быть строго больше нуля. Нулевые дистанция и количество заряда запрещены. Выход за любую границу, нечисловые типы (включая `bool`) и неконечные числа запрещены. Проверки: `TC_M_03`, `TC_M_05`, `TC_M_06`, `TC_M_12`, `TC_M_26`, `TC_M_27`.
2. **Ровно достаточная энергия:** движение с расходом, равным запасу, и смена режима при ровно `10.0`/`5.0` успешны с нулевым остатком; меньший запас вызывает атомарный отказ. `move(0.0, "road")` запрещён даже при полной энергии. Проверки: `TC_M_12`, `TC_M_18`, `TC_M_19`, `TC_M_30`, `TC_S_03`, `TC_S_05`, `TC_S_08`.
3. **Переполнение заряда и несколько причин отказа:** зарядка на `1000.0` при запасе `50.0` даёт ровно `100.0`; при `roll`, энергии `0.0` и поездке по камням первична ошибка режима, а при повторном сворачивании первична ошибка состояния панциря. Проверки: `TC_M_22`, `TC_M_23`, `TC_M_25`, `TC_S_05`.

## 6. Исключения и иерархия

### 6.1. Иерархия

```text
Exception
└── CrazyVehicleError
    └── BasaltSnailError
        ├── UnsupportedTerrainError
        ├── RollingTerrainError
        ├── InsufficientEnergyError
        └── ShellStateError
```

Каждый указанный родитель — непосредственный базовый класс потомка. Доменные ошибки не наследуются от `RuntimeError`, `ValueError` или `TypeError`. Ошибки типа/значения параметров используют стандартные `TypeError`/`ValueError`. Проверка иерархии: `TC_M_31`.

### 6.2. Таблица сообщений

Кавычки в таблице не являются частью сообщений. Сообщения фиксированные, без подстановки чисел.

| Ситуация | Исключение | Точное сообщение |
| --- | --- | --- |
| Неверный тип `name` | `TypeError` | `name must be a string` |
| Пустое имя после `strip()` | `ValueError` | `name must not be empty` |
| Неверный тип `mass_kg` | `TypeError` | `mass_kg must be a number` |
| Неконечная масса или масса вне диапазона | `ValueError` | `mass_kg must be finite and between 100 and 500` |
| Неверный тип `wheel_diameter_m` | `TypeError` | `wheel_diameter_m must be a number` |
| Неконечный диаметр или диаметр вне диапазона | `ValueError` | `wheel_diameter_m must be finite and between 0.5 and 2` |
| Неверный тип `energy` | `TypeError` | `energy must be a number` |
| Неконечная энергия или энергия вне диапазона | `ValueError` | `energy must be finite and between 0 and 100` |
| Неверный тип `distance_km` | `TypeError` | `distance_km must be a number` |
| Неконечная или неположительная дистанция | `ValueError` | `distance_km must be finite and positive` |
| Неверный тип `terrain` | `TypeError` | `terrain must be a string` |
| Неизвестная строка `terrain` | `ValueError` | `unknown terrain` |
| `water` или `air` | `UnsupportedTerrainError` | `basalt snail can only travel on land` |
| `rock` или `sand` в `roll` | `RollingTerrainError` | `rolling is only allowed on road` |
| Недостаточно энергии для движения | `InsufficientEnergyError` | `not enough energy to move` |
| Сворачивание в `roll` | `ShellStateError` | `shell is already folded` |
| Недостаточно энергии для сворачивания | `InsufficientEnergyError` | `not enough energy to fold shell` |
| Раскрытие в `crawl` | `ShellStateError` | `shell is already unfolded` |
| Недостаточно энергии для раскрытия | `InsufficientEnergyError` | `not enough energy to unfold shell` |
| Неверный тип `amount` | `TypeError` | `amount must be a number` |
| Неконечное или неположительное `amount` | `ValueError` | `amount must be finite and positive` |

Для `AttributeError` при присваивании атрибуту или его удалении текст не регламентируется, поскольку зависит от выбранной реализации защиты доступа.

## 7. Что вне рамок

- Графический интерфейс, анимация и физическая симуляция.
- Подземное бурение, прыжки, полёт, плавание, перемещение задним ходом и координаты маршрута.
- Столкновения, препятствия отдельными объектами, повреждения, ремонт и учёт погоды.
- Пользователи, права доступа, база данных, файлы состояния и внешние API.
- Взаимодействие транспортов и уникальность имён.
- Учёт массы пассажира отдельно, изменение габаритов и массы после создания.
- Прямое изменение состояния; автоматическое переключение режима или восстановление энергии.
- Гарантии расчёта для конечных чисел настолько больших/малых, что промежуточные операции выходят за представимость `float`. Обычные конечные входы не ограничиваются дополнительным произвольным пределом.
